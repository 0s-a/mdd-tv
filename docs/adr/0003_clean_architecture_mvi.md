# ADR 0003: تطبيق معمارية Clean Architecture مع نمط إدارة الحالة MVI
# Clean Architecture and MVI Pattern for State Management

* **الحالة:** مقبول (Accepted)
* **التاريخ:** 2026-11-18
* **المشروع:** مدد TV (`mdd_tv`)

---

## 1. السياق والمشكلة (Context & Problem Statement)
تطبيقات الوسائط التفاعلية تتضمن حالات تدفق معقدة وسريعة (تحميل صور البوسترات، نبضات المشغل اللحظية، استجابة إيماءات اللمس، وتحديث البيانات المتزامن). غياب المعمارية المنضبطة يؤدي إلى حدوث Race Conditions وتداخل منطق الأعمال مع واجهة المستخدم، مما يصعّب فحص واختبار الكود آلياً.

---

## 2. البدائل التي تمت دراستها (Considered Options)
* **الخيار الأول (MVVM الكلاسيكي):** استخدام LiveData أو متجهات الحالة القابلة للتعديل داخل الـ ViewModel.
  * *السلبيات:* احتمالية حدوث تغييرات حالة غير متوقعة من عدة مصادر، وصعوبة تتبع تدفق البيانات بدقة.
* **الخيار الثاني (Clean Architecture + MVI أحادي الاتجاه):**
  * عزل طبقة الـ Domain تماماً (كود Kotlin خالص بنسبة 100% بدون أي استيراد لمكتبات أندرويد).
  * تدفق بيانات أحادي الاتجاه (UDF): `Intent -> ViewModel -> Immutable StateFlow -> Compose UI`.

---

## 3. القرار المعتمد (Decision Outcome)
تم اعتماد **الخيار الثاني**: عزل طبقة الـ Domain في حزم مستقلة، واعتماد عقود `Contract` موحدة لكل شاشة تحدد الـ State والـ Intent بوضوح، مع حقن التبعيات عبر `Koin`.

---

## 4. النتائج والتأثيرات (Consequences)
* **الإيجابيات:**
  * استقرار كامل لإعادة الرسم (Recomposition) في Jetpack Compose بفضل كائنات الحالة غير القابلة للتعديل (`Immutable`).
  * سهولة فائقة في كتابة اختبارات الوحدة الصامتة لطبقتي الـ Domain والـ ViewModels دون الحاجة لمحاكيات (Emulators).
* **القيود:**
  * تطلب كتابة كود هيكلي إضافي (UseCases, Contracts, Mappers)، لكنه استثمار أساسي لحماية استقرار التطبيق.
