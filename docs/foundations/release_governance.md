# ميثاق ودليل حوكمة الإصدارات وتوثيق التغييرات
# Release Governance & Changelog Protocol

> **النطاق:** مرجع إلزامي يحدد الإجراءات القياسية (SOP) لإدارة الإصدارات، الترقيم الدلالي، توثيق التغييرات، وأرشفة الحزم لتطبيق "مدد TV".

---

## 1. مبادئ الترقيم الدلالي (Semantic Versioning Protocol)

يتبع التطبيق المعيار العالمي `MAJOR.MINOR.PATCH`:

1. **الترقيم الرئيسي (MAJOR - X.0.0):**
   * يُرفع عند إحداث تغييرات معمارية جذرية تكسر التوافق مع الإصدارات السابقة (Breaking Changes) أو إعادة كتابة شاملة لقواعد البيانات أو مسار الاتصال.
2. **الترقيم الفرعي (MINOR - 1.X.0):**
   * يُرفع عند إضافة وظائف وميزات جديدة متوافقة مع الإصدارات السابقة (Backward-Compatible Features) مثل إضافة مشغل خارجي، أو شاشات جديدة، أو متصفح هرمي.
3. **ترقيم التصحيحات (PATCH - 1.0.X):**
   * يُرفع حصراً عند معالجة أخطاء تشغيلية (Bug Fixes)، إصلاح تسريبات الذاكرة، أو تعديلات التوافق البسيطة دون إضافة ميزات جديدة.
4. **رمز البناء الداخلي لنظام أندرويد (`versionCode`):**
   * عدد صحيح موجب يتزايد حتماً وبشكل رتيب (`+1`) مع كل بناء رسمي يتم توزيعه أو أرشفته لضمان قبول نظام تشغيل أندرويد الترقية دون تعارض.

---

## 2. المصدر الموحد للحقيقة (Single Source of Truth)

* يُحظر تكرار أرقام الإصدارات يدوياً في كود التطبيق.
* يمثل ملف `app/build.gradle.kts` المصدر النهائي للحقيقة:
  * `versionName`: رقم الإصدار الدلالي.
  * `versionCode`: رقم البناء الداخلي.
* يلتزم كود التطبيق في `AppConfig.APP_VERSION` وترويسات الشبكة في `AuthInterceptor.CLIENT_VERSION` بالقراءة والمزامنة المباشرة مع هذه الإعدادات المركزية.

---

## 3. دورة حياة تسجيل التغييرات (Changelog Lifecycle)

```
[التطوير اليومي] ──► [docs/UNRELEASED.md] ──(قرار الإطلاق)──► [CHANGELOG.md] ──► [git tag vX.Y.Z]
```

1. **المخزن الانتقالي المؤقت (`docs/UNRELEASED.md`):**
   * يُسجل فيه كل تعديل فور إنجازه مصنفاً حسب النمط القياسي (`Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`).
2. **السجل الدائم (`CHANGELOG.md`):**
   * عند إطلاق إصدار رسمي، تُفرغ محتويات `UNRELEASED.md` في ترويسة جديدة مؤرخة بصيغة `## [X.Y.Z] - YYYY-MM-DD`.
   * يُعاد تصفير خزان `UNRELEASED.md` لاستقبال الدورة التطويرية التالية.

---

## 4. الإجراءات القياسية السداسية لإطلاق أي إصدار رسمي (Release SOP)

1. **بوابة فحص الجودة (Quality Gate):**
   * تشغيل اختبارات الوحدة: `./gradlew testDebugUnitTest`.
   * تشغيل فحص التحليل الثابت: `./gradlew lintDebug` (شرط إلزامي: صفر أخطاء).
2. **تحديث أرقام الإصدار:**
   * زيادة `versionCode` بمقدار `+1`.
   * ضبط `versionName` وفق المعيار الدلالي في `app/build.gradle.kts` و `AppConfig.kt`.
3. **تفريغ سجل التغييرات:**
   * نقل محتوى `docs/UNRELEASED.md` إلى `CHANGELOG.md`.
4. **تثبيت كوميت الإصدار:**
   * استخدام النمط القياسي: `chore(release): prepare release vX.Y.Z`.
5. **بناء وأرشفة الحزمة:**
   * تشغيل `./gradlew assembleRelease` ليقوم السكربت تلقائياً بأرشفة وتسمية الحزمة في `releases/`.
   * توثيق البصمة الرقمية (SHA-256) في `releases/README.md`.
6. **توثيق وسم Git الدائم:**
   * تسجيل الوسم: `git tag -a vX.Y.Z -m "Release vX.Y.Z: Summary of release"`.
