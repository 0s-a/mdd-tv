## 1. التوصيف العام والدافع (Overview & Motivation)

### 1.1 ملخص الفكرة
إنشاء وتفعيل خطافات Git أوتوماتيكية داخل مستودع المشروع (`.git/hooks/pre-commit` و `.git/hooks/commit-msg` مع توفير سكربت تهيئة في `tools/install_hooks.sh`) لفرض قواعد الدستور المعماري للمشروع لحظياً على جهاز المطور والوكيل الذكي قبل إتمام عملية التثبيت (Commit):
1. **فحص الحظر الشامل للإيموجيات (Zero Emoji Enforcement):** فحص كافة الملفات المجهزة للإيداع (`git diff --cached`) ورفض التثبيت فوراً إذا وُجد أي رمز تعبيري في الكود، التعليقات، أو ملفات التوثيق.
2. **التحقق من رسائل الـ Git (Conventional Commits):** فحص نص رسالة التثبيت للتأكد من التزامها بالصيغة المعتمدة (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`, `perf:`).
3. **معايير تسمية الملفات والمجلدات:** منع إضافة أي ملفات تحوي مسافات أو حروفاً خاصة أو حروفاً كبيرة غير مطابقة لنمط `snake_case` للملفات والوثائق.

### 1.2 الدافع ومبررات الإضافة
* **الحماية الوقائية عند المصدر:** منع تسرب أي إيموجيات أو رسائل غير منضبطة قبل وصولها للمستودع، مما يغني عن عمليات التنظيف اليدوية اللاحقة.
* **أتمتة الحوكمة:** تحويل بنود دستور مساحة العمل (`AGENTS.md`) وقواعد العمل (`OPERATIONAL_RULES.md`) إلى قيود تقنية برمجية صارمة غير قابلة للتجاوز.

## 3. فحص التعارضات المعمارية والبرمجية (Architectural Conflicts Audit)

### 3.1 سرعة التنفيذ وعدم تعطيل سير العمل
* **التعارض المحتمل:** بطء تنفيذ الخطافات إذا تم تضمين أوامر بناء Gradle ثقيلة أثناء كل `git commit`.
* **المعالجة:** قصر فحص الخطاف `pre-commit` على سكربت بايثون/باش سريع للغاية يستغرق أقل من 100 مللي ثانية (فحص نصوص regex فقط)، وترك الفحوصات التجميعية الثقيلة للـ CI السحابي.
